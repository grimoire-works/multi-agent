# 文件格式定义

初始化时需要生成的各类文件格式规范。Skill 执行到 Step 5 时按此格式创建文件。

## .claude/settings.local.json

```json
{
  "permissions": {
    "allow": [
      "Bash({构建命令}:*)",
      "Bash({测试命令}:*)",
      "Bash({依赖安装命令}:*)",
      "Bash(find ~/.claude/projects/:*)",
      "Bash(mkdir -p:*)"
    ]
  }
}
```

## doc/plan.md

**初始化时只生成空模板（仅含 Task 0 环境验证），不自动填充任务。** 具体开发任务由用户提供需求后，通过编排流程委托 PM Agent（`{代号}-pm`）分析拆解生成，或由用户手动填写。

**原因**：初始化阶段不应假设用户要做什么功能，任务规划应在用户明确需求后才进行。

空模板格式：

```markdown
# 开发计划 — {项目名称}

## 项目概述
{一句话描述}

## 任务列表
| # | 任务 | 状态 | DEV_ID | TEST_ID | 涉及文件 | 验收标准 | 备注 |
|---|------|------|--------|---------|----------|----------|------|
| 0 | 环境验证 + 编译检查 | ⏳ 待办 | - | - | - | 构建命令零错误 | 主Agent直接做 |

## 当前进度
- 正在执行：尚未开始
- 已完成：0/0
```

任务填写规范（供 PM Agent 或用户手动填写时参考）：
- 每个任务 100-300 行代码量
- 每个任务定义 3-5 条可执行的验收标准，格式为"操作 → 期望结果"（如"POST /api/register 合法参数 → 返回 201"）
- "涉及文件"列必须填写，用于 Wave 分组时的文件冲突检测。格式为逗号分隔的文件路径（如 `lib/core/audio/pitch.dart, lib/core/models/note.dart`）
- "验收标准"列填写"见 AC-N"并在下方 AC 段落中定义具体标准

## doc/lessons-learned.md

空文件，只写标题：`# 经验教训库`

### 结构化经验格式（v2）

每条经验使用以下格式写入：

```markdown
### EXP-{NNN}: {简短标题}

| 字段 | 值 |
|------|-----|
| 日期 | {mmdd} |
| 触发条件 | {什么场景下会遇到} |
| 域 | {从下方域标签中选 1-2 个} |
| 置信度 | 0.3 |
| 命中次数 | 0 |
| 最后命中 | {mmdd} |
| 来源 | {agent-type}:{task-id} |
| 类型 | bug-fix / prompt-feedback / best-practice / anti-pattern |

**原因**：{为什么会出这个问题}

**解法**：{怎么解决的}
```

### 字段定义

**域标签分类**（agent 写入时从中选择 1-2 个）：
- `backend` — 后端逻辑、API、数据库
- `frontend` — 前端组件、页面、路由
- `testing` — 测试策略、AC 验证
- `architecture` — 架构设计、模块划分
- `performance` — 性能优化、资源管理
- `ui` — UI 样式、布局、动画
- `security` — 安全漏洞、权限控制
- `prompt` — 提示词优化、Agent 指令
- `tooling` — 构建工具、CI/CD、环境配置

**类型分类**：
- `bug-fix` — 修复 bug 后总结的经验
- `prompt-feedback` — prompt 描述不够清晰导致的修正（≥2 轮修正时使用）
- `best-practice` — 开发过程中发现的最佳实践
- `anti-pattern` — 发现的反模式，需要避免

**置信度晋升规则**：
- 0.3 → 新建（默认）
- 0.5 → 命中 1-2 次（由 `/learn` 从 main-log.md 统计注入次数）或来自 diagnose 产出
- 0.7 → 命中 3+ 次
- 0.9 → 已提升为项目规则

**置信度衰减规则**（由 `/learn` 自动执行）：
- `最后命中` 距当前日期 ≥ 30 天 → 置信度 -0.1
- 置信度降到 0.1 以下 → 标记为归档候选

**最后命中字段维护**：
- 新建时：`最后命中` = 创建日期（即与 `日期` 字段相同）
- `/learn` 运行时：从 main-log.md 统计命中次数后，同步更新 `最后命中` 为日志中最后一次注入的日期

### 经验生命周期

```
新建（0.3）→ 被注入命中 → 置信度上升 → 提升为规则（0.9）
                 ↓
           长期未命中 → 置信度衰减 → 归档（移到 archive 文件）
```

### 归档标准（三个条件必须同时满足）

| 条件 | 阈值 | 说明 |
|------|------|------|
| 距上次命中 | ≥ 30 天 | 长时间没人触发 |
| 置信度 | ≤ 0.3 | 从未真正验证 |
| 命中次数 | ≤ 1 | 只被注入过一次 |

### 旧格式（兼容）

```markdown
- [mmdd] 经验描述
  - 原因：为什么会出这个问题
  - 解法：怎么解决的
```

旧格式条目仍然有效，编排器注入时同时匹配新旧格式。`/learn` skill 可建议将旧格式升级为新格式。

## doc/lessons-archive.md

归档经验存储文件。初始化时不创建，由 `/learn` skill 在归档时自动创建。

格式：`# 经验教训归档`

归档条目保持原格式，末尾追加归档信息：

```markdown
### EXP-{NNN}: {标题}

| 字段 | 值 |
|------|-----|
| ... | ...（原有字段不变） |
| 归档日期 | {mmdd} |
| 归档原因 | {衰减/合并/用户手动} |
```

- Agent 和编排器**不读取**此文件
- `/learn` skill **可读取**此文件，用于恢复和跨周期分析
- 归档不是删除，条目可被恢复回活跃文件

写入：`- {yymmdd hhmm} 项目启动，{项目名称}`

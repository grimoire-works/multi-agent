# Learn — 经验复盘与进化

定期审查项目经验教训，评分排序，将高置信度经验提升为项目规则，归档失效经验。

## 触发时机

- 用户说"经验复盘"/"review lessons"/"/learn"
- 项目里程碑完成后（用户主动触发）
- 编排流程全部完成后（编排器自动提示）

## 工作流程

### Step 1：读取解析

Read `doc/lessons-learned.md`，解析所有条目。

如果 `doc/lessons-archive.md` 存在，也读取归档条目（用于恢复检测）。

两种格式都需识别：

**结构化格式**：
```
### EXP-{NNN}: {标题}
| 字段 | 值 |
...
```
提取：EXP-ID、标题、域、置信度、命中次数、最后命中日期、日期、类型、触发条件。

**旧格式**：
```
- [mmdd] {描述}
  - 原因：...
  - 解法：...
```
标记为"旧格式"，在后续步骤中建议升级。

**命中次数统计**：
从 `doc/main-log.md` 中 Grep 日志行统计每个 EXP-ID 被注入的次数：
```
Grep(pattern="注入经验：.*EXP-{NNN}", path="doc/main-log.md")
```
以此结果更新结构化条目中的"命中次数"字段。

**最后命中日期更新**：
同时从日志中提取每个 EXP-ID 最后一次注入的日期，更新条目的 `最后命中` 字段。如果日志中无记录，保持原值不变。

**违反原则统计**（P-00x 标签扫描）：
扫描所有 EXP 条目的「违反原则」字段（如 `P-005 共享资源同步`），按原则编号聚合违反次数。每条原则的违反次数 = 该原则在所有 EXP 中被标注的次数。

同时检查项目规则：
- Glob(pattern=".claude/rules/*.md") — 检查已有项目规则
- 读取每个规则文件，记录已提升的 EXP-ID
- 注意区分 `.claude/rules/principles.md`（通用原则池，不参与提升/归档，仅作为标签来源）和 `.claude/rules/project-specific.md`（项目专属规则，可由 /learn 提升）

### Step 2：衰减处理（自动执行，无需确认）

在评分前先执行衰减，确保评分基于最新状态：

对每条结构化经验，直接读取 `最后命中` 字段：
- 当前日期 - 最后命中日期 ≥ 30 天 → 置信度 -0.1
- 置信度因此降到 0.1 以下 → 标记为"衰减待归档"
- 同时更新该条目的 `最后命中` 字段为本次 /learn 运行日期（因为本次 /learn 正在"命中"它）

更新 lessons-learned.md 中受影响条目的置信度字段（Edit 工具）。

### Step 3：评分排序

对每条经验计算综合评分：

| 维度 | 权重 | 计算方式 |
|------|------|----------|
| 命中率 | 0.4 | 命中次数 / 文件中条目总数（归一化） |
| 置信度 | 0.3 | 直接取置信度值 |
| 类型权重 | 0.2 | anti-pattern: 1.0, best-practice: 0.9, bug-fix: 0.7, prompt-feedback: 0.5 |
| 新鲜度 | 0.1 | 越新越高 |

综合评分 = 各维度加权求和。

### Step 4：识别动作

对每条经验，判断建议动作：

| 动作 | 条件 | 说明 |
|------|------|------|
| PROMOTE | 置信度 ≥ 0.7 且命中 ≥ 3 且尚未提升 | 提升为项目规则 |
| PROMOTE_PRINCIPLE | 某条 P-00x 原则累计违反 ≥ 3 次 | 自动建议追加项目专属规则到 `.claude/rules/project-specific.md`（强化该原则在本项目的执行）|
| ARCHIVE | 距上次命中 ≥ 30天 且 置信度 ≤ 0.3 且 命中 ≤ 1 | 三个条件必须同时满足 |
| MERGE | 与另一条经验域相同 + 触发条件相似 | 合并为一条 |
| RESTORE | 归档文件中的条目被用户指定恢复 | 移回活跃文件 |
| UPGRADE | 旧格式条目 | 升级为结构化格式 |
| KEEP | 不满足其他条件 | 保持现状 |

**PROMOTE_PRINCIPLE 说明**：通用原则（P-001 ~ P-006）是跨项目 meta-rule，本身不需要"提升"。但当某条原则在**本项目**反复被违反（≥3 次），说明通用原则不够，需要追加**项目专属规则**强化执行。例如：P-005（共享资源同步）在本项目违反 5 次 → 建议在 `project-specific.md` 追加 R-XXX：「本项目所有静态文件改动必须同步 bump 所有引用方的版本号（违反 P-005 第 5 次后强制执行）」。

向用户展示复盘报告：

```markdown

- 已提升为规则：{Z} 条

### 衰减结果
已衰减条目（置信度降低）：
| EXP-ID | 标题 | 原置信度 | 新置信度 | 原因 |
|--------|------|---------|---------|------|

### 条目评分
| EXP-ID | 标题 | 置信度 | 命中 | 评分 | 建议动作 |
|--------|------|--------|------|------|----------|

### 建议提升为项目规则
| EXP-ID | 标题 | 域 | 规则摘要 |
|--------|------|-----|---------|

### 建议归档
| EXP-ID | 标题 | 置信度 | 命中 | 最后命中日期 | 归档原因 |
|--------|------|--------|------|------------|---------|

| 条目组 | 原因 |
|--------|------|

|--------|-------------|

### 原则违反统计（P-00x）

| 原则 | 违反次数 | 涉及 EXP | 建议动作 |
|------|---------|---------|---------|
| P-001 AskUserQuestion 门槛 | {N} | EXP-xxx, EXP-xxx | {KEEP / PROMOTE_PRINCIPLE} |

- 排序：违反次数倒序
```

### Step 6：执行用户确认的动作

**提升为项目规则**：

用户确认后，写入 `.claude/rules/{domain}-rules.md`：

```markdown
# {Domain} 规则（自动提升自经验）

> 由 /learn 于 {date} 生成。来源条目见每条规则。

## R-{NNN}: {规则标题}

**触发条件**：{什么情况下应用此规则}

**规则内容**：{从经验的解法中提炼的可执行规则}

**来源经验**：EXP-{XXX}

**违反原则**：{如适用，标注 P-00x}

**验证记录**：命中 {N} 次
```

同时更新 `doc/lessons-learned.md` 中对应条目的置信度为 0.9（已提升）。

**追加项目专属规则（PROMOTE_PRINCIPLE）**：

当某条通用原则在本项目违反 ≥3 次，用户确认后，**追加**到 `.claude/rules/project-specific.md`（不覆盖 principles.md）：

```markdown
## R-{NNN}: {基于 P-00x 强化的项目专属规则}

**触发条件**：{本项目特定场景}

**规则内容**：{P-00x 通用原则 + 本项目的具体执行要求}

**来源原则**：P-{00x}（{原则标题}）

**违反统计**：截至 {date} 共违反 {N} 次，涉及 EXP-{xxx}, EXP-{xxx}, EXP-{xxx}

**强制等级**：高（违反即视为项目规则违反，tester 报告中标"严重"）
```

注意：通用原则 `principles.md` 永不修改，所有项目强化都写到 `project-specific.md`。

**归档条目**：

用户确认后，将条目从 `doc/lessons-learned.md` 移到 `doc/lessons-archive.md`：
1. 如果 `doc/lessons-archive.md` 不存在，创建并写入标题 `# 经验教训归档`
2. 将归档条目追加到 archive 文件（Edit 工具）
3. 从 lessons-learned.md 中删除该条目（Edit 工具）

归档条目格式保持不变，在末尾追加归档信息：
```markdown
### EXP-{NNN}: {标题}

| 字段 | 值 |
|------|-----|
| ... | ...（原有字段不变） |
| 归档日期 | {mmdd} |
| 归档原因 | 30天未命中 + 置信度 ≤ 0.3 + 命中 ≤ 1 次 |
```

**恢复条目**：

用户指定要恢复的归档条目：
1. 从 `doc/lessons-archive.md` 中读取条目内容
2. 移回 `doc/lessons-learned.md`（追加到末尾）
3. 从 archive 文件中删除该条目
4. 置信度恢复为 0.3（重新开始验证）

**合并条目**：

用户确认合并文本后，用 Edit 删除旧条目、更新保留条目的内容。被合并的条目归档（知识已在目标条目中保留）。

**升级格式**：

用户确认后，将旧格式条目改写为结构化格式。写入前先 Grep `### EXP-` 获取最大编号。

### Step 7：进化管道状态

报告结束后，展示三级进化管道状态：

```
进化管道：
  Level 1 活跃经验：{N} 条（doc/lessons-learned.md）
  Level 1 归档经验：{M} 条（doc/lessons-archive.md）
  Level 2 项目规则：{X} 条（.claude/rules/）
  Level 3 全局规则：需手动提升到 ~/.claude/rules/

  活跃文件健康度：{良好 / 需关注}
  - {N} ≤ 20 条 → 良好
  - {N} > 20 条 → 建议更频繁运行 /learn
```

## 进化管道（三级）

### Level 1：经验条目（doc/lessons-learned.md）

开发过程中自动积累，Agent 修正后追加。日常存储层。

生命周期：
- 新建 → 置信度 0.3
- 被注入 → 置信度上升（由 /learn 统计）
- 长期未命中 → 衰减（置信度 -0.1/30天）
- 衰减到底 → 归档到 doc/lessons-archive.md
- 高价值 → 提升为 Level 2 项目规则

### Level 2：项目规则（.claude/rules/）

从高置信度经验提升，所有 Agent 在工作时都会读取遵守。项目级约束。

提升条件：
- 置信度 ≥ 0.7
- 命中次数 ≥ 3
- 用户确认提升

### Level 3：全局规则（~/.claude/rules/）

跨项目验证的模式，适用于所有项目。手动提升。

建议条件：
- 已在 2+ 个项目中作为项目规则存在
- 用户确认适用于全局

## 注意事项

- ⚠️ 对 `doc/lessons-learned.md` 和 `doc/lessons-archive.md` 的所有修改必须使用 Edit 工具，禁止 Write 覆盖
- ⚠️ 提升为规则后，原条目保留在 lessons-learned.md 中（置信度更新为 0.9），不删除
- ⚠️ 归档不是删除，归档条目仍可被 /learn 读取和恢复
- ⚠️ 旧格式条目不强制升级，仅在用户确认后执行
- ⚠️ 衰减自动执行无需确认，但归档需要用户确认
